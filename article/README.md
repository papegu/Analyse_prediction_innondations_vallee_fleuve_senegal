# Reproducing the Senegal River Valley flood analyses

## Project contents

- `springer_flood_agriculture.tex`: source manuscript present before this review.
- `springer_flood_agriculture.pre_revision.tex`: byte-for-byte backup made before the review changes.
- `IJRS_flood_agriculture_revised.tex`: scientifically revised working copy. It still uses the Springer Nature `sn-jnl` class and is **not** in the Taylor & Francis submission format.
- `references.bib`: bibliography used by the manuscript.
- `analyse_complete.py` and `analyse_exploratoire_modeles.py`: main tabular analysis and model workflows.
- `analyse_validation_spatiale_buffer.py`: additional buffered spatial validation.
- `audit_sensibilite_seuils.py`: read-only validation of the raw threshold-sensitivity exports and their point-key agreement with the main dataset.
- `export_impact_agricole_gee.js`: Google Earth Engine workflow for 10-m aggregate exposure exports.
- `resultats_inondations/`: derived tables, figures, predictions, and validation outputs.
- `resultats_inondations/sensibilite_*.csv`: derived sensitivity summaries reproduced or checked against the raw point and area exports now present in this folder. These satellite-proxy results are not independent ground-truth validation.
- `../dataset_vfs_ml_2019_2024.csv`: point-period input table (19,200 rows).

## Python environment

The scripts use the packages listed in `requirements.txt`. Those entries are not version-pinned; create and archive a tested lock file before claiming bit-for-bit reproducibility. The Earth Engine export additionally requires an authenticated Google Earth Engine account and access to the project assets.

From the repository root, install the packages and run the main analysis:

```powershell
python -m pip install -r article\requirements.txt
python article\analyse_complete.py
```

The main workflow reads the CSV at the repository root and writes its outputs to `article\resultats_inondations\`. It regenerates many existing outputs; preserve the current results directory before rerunning it if those files must be retained for comparison.

The buffered validation reuses the saved five-block site assignments generated by the main workflow:

```powershell
python article\analyse_validation_spatiale_buffer.py
```

It evaluates Random Forest and persistence on 2019--2023, uses a geodesic buffer equal to the empirical 90th percentile of nearest-neighbour site distances, and writes per-block and summary CSVs to `article\resultats_inondations\`. It does not replace the original unbuffered results.

To reproduce the agricultural exposure export, open `export_impact_agricole_gee.js` in the Earth Engine Code Editor, verify access to the referenced assets, and run the export tasks. The Earth Engine exports are not executed by the local Python scripts.

## Threshold-sensitivity export audit

The GEE script `export_sensibilites_seuils_gee.js` is intended to produce these two source files:

- `sensibilite_labels_points_VV_2019_2024.csv`
- `sensibilite_superficies_VV_DW_2019_2024.csv`

Place both files in `article\resultats_inondations\`, then run this read-only audit from the repository root:

```powershell
python article\audit_sensibilite_seuils.py
```

The audit checks file presence, columns, row counts, year/period coverage, duplicate join keys, missing values, binary label values, and agreement of the -16 dB labels with the main dataset using `point_id`, year, and period. It also checks period metadata and the area and percentage fields. It writes no files. The two exports are now present and the audit passes: the 19,200 point-period rows agree with the main dataset on valid -16 dB labels, and the 96 area periods reproduce the existing summaries within floating-point tolerance. Three periods without Sentinel-1 acquisitions are treated as unobserved, not as zero inundation. Reproduced sensitivity summaries are reported in the revised manuscript, but remain satellite-proxy sensitivities, not independent validation.

## Data and reproducibility limits

The raw point-label and area-sensitivity CSVs for Sentinel-1 VV thresholds of -14, -16, and -18 dB and Dynamic World crop-probability thresholds of 0.20, 0.30, and 0.40 are present in `resultats_inondations/` and pass the read-only audit. The raw source rasters are not archived, so pixel-level threshold calculations cannot be independently regenerated from imagery. Periods without Sentinel-1 acquisitions must be treated as unobserved, not as zero inundation. The separate historical flood-area series is retained unchanged and is not interchangeable with 10-m sensitivity outputs.

The separately mentioned `SPI_2024-08-31_10m.tif` was not found. The SPI source Earth Engine code is also absent. The RGB GeoTIFF map tiles are visual products rather than analysis-ready backscatter or class-probability rasters.

The 200 sites are repeated spatial units across 96 ten-day periods; the 19,200 rows are not independent sites. The sampling design and independent flood, crop, damage, yield, and economic reference data are not included. Do not interpret potential agricultural exposure as crop destruction or measured economic loss.
